# 网络代理

网络代理用于给指定渠道建立独立的出站路径。代理资料保存在数据库中，认证信息仅以应用密钥加密保存；渠道只保存代理 ID。未绑定代理的渠道始终直连，绝不读取 `HTTP_PROXY`、`HTTPS_PROXY` 或其他进程环境代理。

## 支持的出口类型

| 协议 | 地址形式 | 用途 |
| --- | --- | --- |
| HTTP | `http://user:password@host:port` | 普通 HTTP CONNECT 代理。通过它访问 HTTPS 渠道仍是正常用法。 |
| HTTPS | `https://user:password@host:port` | 与代理服务器之间使用 TLS 的 HTTP 代理。 |
| SOCKS5 | `socks5://user:password@host:port` | 支持认证的 SOCKS5 出口；`socks5h://` 导入时规范化为 SOCKS5。 |

HTTP/HTTPS/SOCKS5 是 Go HTTP 客户端可直接、低开销使用的出口协议。BridgeOps 不内置 VLESS、VMess、Trojan、Shadowsocks、Hysteria、TUIC、WireGuard 等节点协议栈，不能把这类分享链接误当作可直接转发的代理。

如果代理服务来自 3x-ui、机场订阅或其他节点提供方，请先由 Mihomo/Clash、Xray 或 sing-box 建立标准 HTTP/SOCKS 出口，再把该出口地址加入 BridgeOps。Mihomo 的 `mixed-port` 就是常见选择。这样节点协议与 API 转发进程解耦，失败和资源占用不会扩散到网关本身。

## 导入

网络代理页支持以下来源：

- 手工创建单个 HTTP、HTTPS 或 SOCKS5 端点；
- 多行地址：每行一个完整 URI，或 `host:port[:username:password]`；
- Clash/Mihomo YAML：只导入其中原生 `http`、`socks5`/`socks5h` 节点；要求跳过 TLS 校验的节点会被拒绝；
- 3x-ui 的 Base64/URI 列表：只导入其中的 HTTP/SOCKS 出口，其他节点会列为跳过项并给出原因；
- 公开订阅 URL：服务端只允许 HTTP/HTTPS，最多 3 次跳转和 2 MiB 内容；解析到回环、私有、链路本地、CGNAT、文档保留地址或其他非公网地址时拒绝抓取。私有网络订阅请直接复制内容后粘贴导入。

单次导入最多保存 500 个标准出口，并最多返回 100 条跳过原因，避免异常订阅占满管理数据库或压垮服务。可分批导入其余端点。

Clash/Mihomo 的节点名称一律不作为显示或持久化名称使用。每个可导入节点都改用规范化的 `host:port` 显示名，跳过项只显示稳定序号；因此订阅名称中的 URI、userinfo、query、token 或密码不会进入名称、API 或 UI。手工创建或更新包含同类敏感形式的名称会被拒绝。首次使用网络代理存储时，旧 Clash 记录和含敏感形式的旧记录也会一次性持久化归一为安全名称；若与现有名称冲突，系统使用受限长度的序号后缀。导入结果不会回显密码、完整订阅 URL 或原始节点链接。

手工创建和更新请求限制为 32 KiB；名称、主机、用户名和密码分别最多 128、255、256 和 4096 字节。超限请求在保存或加密前被拒绝。

## 渠道绑定与故障边界

在渠道编辑窗口选择一个已启用的网络代理，系统把该代理 ID 写入渠道。登录、会话续期、余额/倍率同步、模型能力同步、延迟探测、掺水检测和实际网关转发都会复用同一渠道解析结果。

- 一个代理可以绑定多个渠道；不同代理不会共用 HTTP 客户端缓存。
- 客户端缓存只用“代理 ID + 修订时间”作为键，不保存原始 URL 或密码。
- 修改代理后会得到新的缓存键；旧连接最多保留到现有有界空闲连接自然回收。
- 禁用、删除或无法解密已绑定代理时，该渠道请求明确失败；不会悄悄直连。删除已绑定代理会被拒绝，必须先在渠道中解绑或改绑。
- 渠道绑定和代理删除以同一代理记录为并发边界，并由数据库外键兜底；并发操作不会留下悬空的 `network_proxy_id`。
- `network_proxy_id` 是渠道网络出口的唯一来源。未绑定的渠道明确直连，不读取进程的 `HTTP_PROXY`、`HTTPS_PROXY`、`ALL_PROXY` 或系统服务代理配置。
- 旧版本仅设置 `proxy_enabled` 的渠道会在服务启动前一次性迁移：旧系统代理已启用且配置有效时，系统创建或复用一个加密保存的“已迁移系统代理”记录并绑定原有渠道；旧系统代理关闭时，旧渠道会被明确改为直连。旧配置无效时受影响渠道保持故障关闭，不允许静默回退到直连。
- 渠道登录过程中的 Turnstile 解题、会话续期、余额/倍率同步、模型能力同步、延迟探测、掺水检测、最终费用对账和实际网关转发都复用同一渠道出口。系统服务代理仍只服务于通知、独立打码余额刷新和版本检测，不会改变渠道流量。

“纯净 IP”只是管理员用于筛选和管理的低饱和标签，不改变协议、健康状态或路由评分。

## 测试与安全

测试动作通过所选代理访问多个公开出口 IP 服务，记录出口 IP、延迟、测试时间和脱敏错误。测试响应体限制为 64 KiB，模型/延迟探测响应限制为 1 MiB，避免异常上游占用无界内存。测试结果供管理员核验，不会自动把代理切换给其他渠道，也不会把凭据写入日志、列表、使用记录或下游响应。

所有下游公开响应继续使用中性服务文案。网络拓扑、供应商实现、代理地址、订阅链接、账号和密码只留在受保护的管理员配置或审计边界内。
