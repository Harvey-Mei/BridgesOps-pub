# 生图操作能力与任务恢复边界

BridgeOps 为付费生图请求维护独立的结构化操作能力记录。该记录按当前的
`渠道 + 规范分组 + presence generation + 模型 + 操作 + 协议` 隔离，不与普通模型支持能力混用。

当前支持描述两种入口：

- `openai_images`：`POST /v1/images/generations`
- `openai_responses`：`POST /v1/responses` 中明确声明 `image_generation`

每条记录可描述同步、异步、同步与异步均已确认或未知任务模式、幂等请求头支持、任务 ID 的结构化 JSON 路径、
安全 `GET` 查询路径模板、状态 JSON 路径以及成功和失败终态。记录还包含证据来源、观察时间和
能力版本；管理员页面只展示这些规范化字段，不展示任务 ID、幂等键值、凭据、代理、站点 origin
或原始上游响应。

## 允许的证据来源

能力只能来自以下三类证据：

1. `observed_success`：正常用户发起且真实成功的请求。BridgeOps 只在请求完成后解析结构化字段，
   不为收集能力额外发起请求。管理员连通性测试、延迟探测、模型检测和其它内部请求不进入该证据源。
2. `provider_metadata`：无需付费图片 POST 即可获得的结构化服务元数据。
3. `admin_config`：管理员显式配置。

证据优先级为管理员配置、服务元数据、成功请求观察。低优先级证据不能覆盖高优先级记录。
同来源的迟到旧证据也不能覆盖较新的观察；同一操作分别观察到同步和异步成功时会合并为双模式。
每次应用或拒绝覆盖都会写入追加式审计；审计只保存规范化能力快照和可选请求日志 ID。

普通 Responses SSE 的 `response.created` / `response.in_progress` 只是生命周期帧，不作为异步任务证据。
非后台请求只有出现带图像结果的完整 `response.completed` 才确认同步模式；异步模式必须由明确的
`background: true` 请求及结构化任务 ID/状态响应，或 Images API 的结构化任务信封确认。
下游请求携带幂等头，或上游只原样回显该头，都不足以确认幂等语义；真实请求观察还必须收到明确的
幂等状态或重放状态响应头，否则保持“未知”。

禁止根据模型名、分组名、渠道名或错误文案推断能力，也禁止通过付费生图 POST 自动探测。

## 失败关闭与不重放

结构化能力目前只用于安全查看和配置，不会开启自动恢复。管理员即使完整填写幂等、任务 ID、
查询路径和终态映射，API 仍返回：

- `recovery_complete: false`
- `automatic_replay_allowed: false`
- `gateway_task_recovery_not_implemented` 恢复阻塞项

因此现有不重放边界保持不变：智能路由在请求发给上游前可因 Key 或目标准备失败选择其他候选；固定路由只允许配置的单一渠道/分组，准备失败也直接返回错误。付费生图
请求一旦发出，任何 transport、超时、响应读取、结构化错误或瞬态 HTTP 失败都不会在同渠道重试，
也不会跨渠道回退。智能路由可按既有跨请求规则记录最多一次故障；固定路由不写入或清除智能路由故障、冷却或亲和状态。下游只收到固定脱敏错误，详细脱敏原因只进入管理员请求审计。

只有在未来同时实现并验证提交身份持久化、任务 ID 安全提取、任务查询、终态解释、响应重建和
完整审计后，才能另行评审任务恢复。单独观察到任务 ID 或幂等请求头绝不能放宽不重放保护。

## 管理接口

- `GET /api/gateway/image-operation-capabilities`
- `PATCH /api/gateway/image-operation-capabilities`
- `GET /api/gateway/image-operation-capabilities/:id/audit`

更新使用 `expected_version` 做乐观并发控制，并在写入时再次核对当前 upstream-group presence
generation。旧 generation 的迟到响应或管理员页面不会改写当前能力；审计接口按时间倒序返回
最近 100 条规范化记录，避免管理页面无界读取历史。

管理工作台可按渠道折叠并搜索、筛选后批量选择已同步目标，再将一份管理员显式配置应用到多个
目标。批量操作先预览新建与更新数量并要求确认；浏览器最多并发提交 3 个独立的 `PATCH`，每一项
仍带自己的 `expected_version`，因此它不是用旧版本覆盖多个能力事实的“整批写入”。取消会停止尚未
发出的项目，已在途项目保留“结果未知、未假定保存”的逐项反馈。版本冲突、分组代次变化和目标消失
不会自动重试或被掩盖；只有普通失败或已取消项可由管理员显式重试，冲突必须刷新目标后重新确认。
