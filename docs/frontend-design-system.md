# BridgeOps 前端设计规范

本文件是 BridgeOps 前端的可更新设计基线。新增页面、组件或大范围视觉改动前先遵守本规范；当产品需求确实需要新的视觉语言时，在同一改动中更新本文档并说明变化原因。

## 目标

- 面向运营后台：信息密度适中、可扫描、重复操作稳定，不做营销页式大标题或装饰性卡片堆叠。
- 以渠道管理页、密钥管理页、使用记录页和费用统计页的现有实现为基线，保持跨页面的标题、指标、表格和筛选节奏一致。
- 沿用登录页的细边框、圆角和桥形标志，后台采用柔和蓝色与白色卡片，保留紧凑的信息密度；状态色只承担状态语义。

## 颜色与主题

- 优先使用 `frontend/app/globals.css` 中的语义 token：`background`、`card`、`muted`、`border`、`brand`、`success`、`warning`、`danger`。
- 默认背景为冷浅灰 `#f5f7fa`、卡片为白色，深色主题使用蓝灰层级。`primary`/`brand` 使用低饱和蓝色 `#4774aa`（深色主题为 `#9bbde5`），`accent` 为浅蓝选中态，`info-surface` 为极浅蓝信息面；普通卡片不铺满蓝色，指标数字默认使用正文色。
- 绿色只表示健康、已对账或完成；黄色表示暂缓、待确认或待对账；红色表示失败、风险或错误。普通数据不用红绿黄抢占注意力。
- 图表可以使用现有 chart token 或低饱和蓝、青、琥珀色区分数据系列；图例、悬浮提示与数据含义必须一致。
- 趋势分析中的同一数据语义必须跨图表保持稳定配色：存量使用蓝色、消费使用琥珀色、涨价使用珊瑚红、降价使用青绿色、混合调整使用紫灰色。页面级色板必须同时提供明暗主题值，并保留文字图例，不能只靠颜色传达含义。
- 深色主题继续依赖同一组语义 token，不要为单个页面硬编码仅浅色模式可见的背景色。

## 页面骨架

- 使用 `PageHeader` 作为一级页面标题。页面标题图标必须与侧边栏同一入口的图标一致；若图标不准确，应同时替换两处。
- `PageHeader` 常驻一行简短副标题，说明当前页面的范围或口径。长说明和换算细节才放 Tooltip，不能把必要信息全部隐藏。
- 页面常用垂直间距为 `space-y-4` 或 `space-y-5`；大屏内容应充分使用可用宽度，不人为做窄列布局。
- 页面分区使用独立的圆角面板，而不是把所有区域放进一个带分隔线的大容器。不要在面板内再堆叠视觉相同的卡片。

- 后台侧栏与浏览器图标使用登录页同款拱桥标志；侧栏当前入口使用浅蓝底与蓝色文字，悬浮保持同一配色；后台桥形标志使用蓝底白色线条（深色主题为浅蓝底深蓝线条），浏览器图标同步。折叠态仍保留 40px 导航命中区域。
- 后台页面标题使用 40px 细边框图标容器，卡片默认圆角 16px、细边框和轻阴影；指标卡使用纯色卡片，最小高度 112px，主数字为 30px、宽屏为 34px，标题行与数字统一居中，状态通过图标、数值和文字表达。按钮、输入框和选择器默认圆角 8px、高 36px，紧凑操作可保持 32px；弹窗使用 16px 圆角。不复用登录页的大尺寸表单和装饰动画。

## 登录与会话验证页

- 登录入口采用深浅蓝灰分栏：桌面左侧为深蓝灰底大字 `BRIDGE / OPS` 品牌区，右侧卡片只保留一行单色桥形标志与品牌名称，以及账号、密码和登录按钮；不重复展示“管理中心”、登录说明或边角品牌文字。桥形标志采用单一向上拱弧、平直桥面和短竖向支撑构成的线条 SVG，避免独立尖塔轮廓；与后台和提交按钮共用柔和蓝色。品牌大字只作装饰，对辅助技术隐藏；登录页不展示业务功能卡片、渠道类型或实现拓扑。
- 卡片最大宽度为 400px，使用 24px 圆角、细边框和轻阴影；52px 标志与品牌名称左对齐，标题行下设细分隔线。输入框高 54px、圆角 12px，字段标签使用小号中性色；提交按钮高 52px，文字与向右箭头分置两端。视觉文案精简时仍须保留读屏可识别的登录标题、输入标签和密码显隐按钮名称，不保存密码到浏览器存储。
- 左侧以低对比网格、1.5px 轨道（淡蓝色 18% 不透明度，内圈再降至 75%）、8px 光点、柔和光晕和不超过 8px 的文字浮动提供装饰动画。轨道圆心靠近左上角（距上、左各 8%，直径为面板宽度 120%），由面板裁切，只呈现局部圆弧。轨道只作衬托，以光点体现运动，不能抢过品牌文字。只用 CSS 的 transform/opacity 动画，不引入画布、持续脚本或网络请求；仅在桌面且 `prefers-reduced-motion: no-preference` 时运行，小屏及减少动态效果模式保留静态图形。
- 右侧保留浅蓝灰/深蓝灰背景、淡点阵和低对比连接线，卡片保持纯色实底。装饰不拦截指针且对辅助技术隐藏，不能降低表单文字对比度；背景 token 使用 `--auth-panel` 和 `--auth-pattern`，只作用于登录入口。
- 登录入口独立使用限定在 `.auth-screen` 内的 `--auth-background`、`--auth-foreground`、`--auth-muted`、`--auth-border`、`--auth-control`、`--auth-action`、`--auth-action-foreground` 独立 token，同时定义明暗主题，与后台共享柔和蓝色；分栏、点阵和动画只用于登录入口。
- 1024px 以下隐藏左侧装饰区，表单保留安全边距并允许小高度视口纵向滚动。会话验证占位复用同一布局，避免加载完成时切换页面骨架。
- 登录失败使用固定短提示和 `role="alert"`；提交时显示加载状态并禁止重复提交。保留原有账号密码与 HttpOnly 会话机制，不为模仿外观增加服务地址、管理 Key、语言或记住密码等未支持的设置。
- 首次访问的服务器 `/login` 页面与 React 会话失效页保持相同视觉骨架。服务器页面继续使用无脚本的原生表单和内联品牌 SVG，保持现有 CSP、表单跳转和后台资源鉴权；密码显隐、提交中状态仅用于支持脚本的 React 入口。服务器页按系统偏好提供明暗主题。

## 不可破坏的布局约束

以下规则是已经确认的产品约束，优先级高于单个页面的临时实现便利：

- 表格、列表和指标区的尺寸必须稳定。错误原文、日志、堆栈、上游返回或长说明不得直接渲染在表格单元格中，也不得改变列宽或行高；表格内只显示固定尺寸的状态标签，异常统一使用红色“异常”标签。
- 表格单元格中的标签、分组或长内容被截断时，点击固定高度的预览区域后必须在相邻 `Popover` 中完整展示；悬浮层内部自行滚动，禁止在表格行内展开或推动页面布局。
- 点击异常标签后使用 Dialog 查看完整内容。标题必须带当前对象上下文，例如“Tokora · 异常详情”；正文放在有最大高度、可滚动并保留换行的区域；提供带复制图标的“一键复制”按钮，并用 Toast 反馈成功或失败。
- 使用记录详情中的故障回退与会话亲和轨迹必须按事件逐行展示，不能把多个候选、错误和最终选择挤在同一行；亲和记录必须显示来源请求与原本正常候选排名，复制内容保留相同换行结构。
- 路由详情弹窗桌面可使用 1240px 宽度。每次失败尝试用一个紧凑条目：编号、渠道/分组、HTTP 状态、已发起标记、正常排名和首字预算横向排列，原因及具体故障紧随其后，不重复“失败候选”标题和内层告警卡片。首字预算不能冒充实际耗时。长故障文本在条目内有界滚动并可完整复制；最终结果同行显示目标与排名。亲和来源及有效期同行，被覆盖候选仍逐条展示。排除快照保留当时版本、采集时间、覆盖范围、generation 和冷却事实，缺失说明压成一行，不使用当前状态推断历史。
- 渠道余额阈值最低为 0.1；余额低于有效阈值时，所有分组统一显示为暂停路由，不能只在某个候选或密钥页面局部标记。
- 表格正文默认上下居中。状态、数值、操作和短标签默认左右居中；只有名称、身份或需要连续阅读的长文本列可以左对齐。任何局部 `max-width` 都不能把本来有足够列宽的标签或色块挤成小块。
- 名称后的主页链接、状态或路由标签必须作为紧邻的内联附属信息排列，不能用弹性占位把它们推到单元格末端；名称过长时只截断名称，并为图标和标签保留稳定空间。
- 页面和面板必须使用可用宽度，但每一列都要有明确宽度预算。增加或缩减某列时要检查相邻列，不能靠内容自然撑开，也不能用内联展开、下拉编辑或长文本突然推动整体布局。
- 桌面侧栏折叠后只保留紧凑图标轨道；品牌标志与导航图标使用一致的固定容器，导航按钮仍保留至少 40px 命中区域。折叠态不得为了品牌标志保留展开宽度，也不得把普通导航图标缩成难以识别的小图标。
- 复杂查看、编辑、候选管理、自定义时间和手动固定模型等操作使用 Dialog 或 Popover。静态状态只显示普通标签，进入编辑后才显示选择控件；弹窗标题必须包含当前分组和对象名称。
- 汇总多个渠道的分组表格在桌面使用视口宽度的 80%–90%，并让表格占满弹窗剩余高度；移动端保留安全边距，表格设置稳定最小宽度并在自身区域横向滚动，不能撑宽页面。
- 页面级指标优先组成一个宽阔的摘要区域，使用轻分隔和统一的标题、数字层级；不再把每个数字包成独立小方块。确有不同任务语义时才使用独立卡片。
- 页面标题、面板标题和侧边栏入口使用统一的图标和字体层级。页面范围、关键字段标签和决定操作的信息直接显示；重复教学文案及复杂换算放入 Tooltip。
- 使用记录的下游 IP 定位只可通过管理员后端的本地定位库完成，浏览器不得把记录 IP 发送给第三方服务。同一列表中相同的规范化 IP 必须共享查询中、成功和失败状态，一行完成查询后其它相同 IP 行立即复用结果，不能按请求记录 ID 重复查询。位置主标签只按可用精度显示“城市 · 州/省 · 国家代码”，不得加入“城市估算”“地区级”“国家级”或网络出口类型前缀；精度和网络类型放在详情中。城市、邮编和坐标必须同时具备已识别的普通网络、ASN 归属和可验证的精度半径；CDN、代理、云出口或精度不足时只显示国家/地区及对应原因。
- 使用记录的首字延迟使用语义色分三级：10 秒内为健康、10–30 秒为警示、超过 30 秒为危险，数值和 Tooltip 仍须说明区间，不能只靠颜色传达。超过 30 秒、日志有真实路由且规范化 `route_reason` 为 `smart_primary`、`fallback`、`session_affinity` 或 `model_filtered` 时，在数值旁显示不大于 20px 的雪花 icon-only 按钮；固定路由、内部请求和未知路由原因默认不显示。Tooltip 说明它会按该日志实际命中的渠道/分组进入配置时长的智能路由冷却，点击后必须立即显示 loading，并用 Toast 报告成功或错误。
- 默认非状态表面使用白色、冷浅灰或极浅蓝色；红、绿、黄只承担错误、健康和暂缓等状态语义。图表系列、模型品牌与分组身份颜色保留各自的辨识作用。
- 同一分组使用稳定、低饱和且彼此可区分的柔和标签色；分组标签可辅助扫描，但不能与状态色混淆。分组或多标签内容折叠后，整个内容区域都应可点击展开，不只依赖很小的图标按钮。
- 刷新、同步、测试等按钮点击后必须立刻显示旋转、禁用、进度或结果反馈。图表联动页面的同组图表必须共享悬浮索引，时间轴、绘图区上下边界和固定高度保持对齐；密集时间刻度可以斜排，但轴高和 Tooltip 占位必须固定，悬浮状态不得改变容器尺寸或滚动范围。曲线 Tooltip 应按光标所在半区向可用一侧展开，并在中线保留死区；完整内容应通过合理宽度和换行展示，不使用 Tooltip 内部滚动条。
- 大数字必须走 `frontend/lib/format.ts` 的共享紧凑格式，不能在页面内另写单位换算。Token 使用 `K/M/B`，保留最多两位小数；其它计数使用 `K`，达到百万后使用科学计数 `E`，同样保留最多两位小数。完整精度只在确有核对价值的详情区或 Tooltip 中展示。

## 指标面板

- 复用 `StatusMetricCard` 展示一组同层级指标。同行指标使用相同高度、内边距、图标尺寸和数字层级。
- 全站页面级指标卡采用居中排布：图标与标题组成紧凑的居中标题行，主数字在下方独立居中；不再把图标固定在右上角或为标题保留单侧空位。长标题与长数值截断时保留完整提示，统计卡的点击、键盘操作和状态含义保持一致；列表、表格和表单沿用各自的对齐规则。
- 指标值默认用 `text-3xl` 或页面已有的紧凑规格；只在真正的概览首屏使用更大的数字。数字必须使用 `tabular-nums` 或组件默认格式，防止跳动。
- 每张指标面板只放一个主值；细节通过 Tooltip 的 `hint` 提供，不在面板底部堆说明句。
- 指标代表待处理异常时可以做成键盘可达的点击目标；点击后定位默认排序中的第一项异常，而不是在卡片里塞进操作按钮或解释段落。

## 面板、筛选与表格

- 标准分析面板：独立边框、浅色表头、统一 `h-12` 标题栏和 `p-4` 内容区。标题使用 `text-lg font-semibold`。
- 筛选条件紧贴其影响的数据区域。筛选面板可在标题栏显示当前条数和已筛选计数，但不要另设“当前筛选结果”横条或无关刷新按钮。
- 表格默认保持列宽预算明确、行内容垂直居中。渠道管理等业务表默认将状态、操作和数值单元格居中；长名称列可左对齐并截断。
- 表头、正文和分页必须使用同一宽度模型。不要用展开式下拉框撑开表格行；复杂编辑操作使用 Dialog 或 Popover，并在标题里标明当前分组和对象名称。
- 分组身份可以使用低饱和的稳定标签色帮助扫描，同一分组应始终使用同一种颜色；这类颜色不得表示健康、风险或其他状态，未分组使用默认中性标签。
- 候选分组管理和固定候选弹窗必须保留所有结构有效的分组，允许新增、勾选或固定；历史探测开关不再参与恢复、智能路由或固定路由，也不得作为状态标签重新出现在界面。选择候选分组的雷达属性时，只要求当前所选成员中至少一个具有该家族的同步事实；不得按家族逐项隐藏候选，也不得在切换雷达属性时删除其它已选成员。智能路由预览仍应独立显示真实健康门禁和不可用原因。候选管理必须使用从 1 到末位的全局平铺路由排名，不得按渠道分段、折叠或重新编号；搜索、状态和协议筛选只控制可见项，不能改变完整候选顺序。数百候选场景必须支持搜索及状态、协议筛选；同一渠道和上游分组的多协议投影聚合为一项。既有成员暂时不在当前候选快照中时必须以“当前不可见”保留显示和选择，只有用户明确取消选择并保存才可移除，不能因加载或刷新窗口静默丢失。批量加入或移除当前筛选结果必须先预览数量和目标再确认，筛选、单选、批量预览和确认均须支持键盘操作。
- 上游健康视图中处于路由冷却的分组在状态旁显示“一键启用”，点击后立即进入 loading 并刷新列表；操作只清除当前稳定分组和 current generation 的路由失败链/冷却，不改变 Key 状态。Key 缺失、停用、provisioning 或 generation 不完整时按钮保持禁用并通过可见说明或 `title` 给出结构原因。请求必须使用 generation-scoped 幂等键，成功、幂等重放和错误都用 Toast 明确反馈。
- 下游 Key 的候选禁用是 Key 级路由排除，候选管理标题、按钮和结果反馈必须明确“仅影响当前 Key”。它不能伪装成渠道或分组的全局停用，也不能删除禁用前的使用与回退审计记录。
- 候选管理中的模型只用于模拟该请求场景下的候选排序和可用性，不修改 Key 配置或实际路由。界面必须称为“路由预览模型”，并按下游 Key 在当前浏览器保留管理员上次选择。可选项必须来自当前候选组、协议、模型家族的已同步模型，不得把缺失模型重新注入选项；已手选的模型暂缺时保留名称并暂停预览，未手选时依次使用当前映射结果、最近真实请求模型和可用默认模型。
- 固定路由选择器必须支持按渠道和分组搜索；当前 Key 禁用、路由冷却、渠道监控暂停、暂时渠道错误或低余额只作为状态提示，不得使候选不可选择，也不得阻止固定请求直通。固定模式只向配置目标发起一次请求，不应用智能首字超时、确认重试、候选回退、路由故障/冷却或会话亲和。渠道或分组的缓存异常仍允许保存固定选择，真实请求继续向该目标发起一次转发；只有实际 Key/目标解析或上游转发失败才明确报错，不能根据缓存异常预先拒绝，也不能静默切换到其它候选。缓存中的 `gateway_app_mismatch` / `no_supported_gateway_app` 仅是智能探测或能力提示，不得阻止固定选择。候选因渠道/分组缺失，或本地 Key 缺失、停用、provisioning、无密文等可证明的结构性条件不可选择时，必须在候选行内直接显示全部阻断原因，不能只显示“当前不可选择”或仅依赖 Tooltip。
- 密钥管理的模型映射是表格内独立的高频设置，不依赖右侧整行修改按钮。关闭时显示“按下游请求选择”；打开后在同一列的 Popover 中显示策略、固定模型和思考选项，并使用该列自己的保存与取消操作。候选分组不支持映射时必须常驻显示原因并通过 `aria-describedby` 关联开关，不能只依赖禁用态 Tooltip，也不能让无效配置进入保存请求。只有候选分组目标实际变化时才做切组预检，改名、调整 Key 分组等无关修改不得因模型事实尚未加载而被拦截。已启用映射的 Key 切换候选分组或独立保存映射时必须重新校验模型家族，manual 策略还必须基于目标分组全部成员真实同步的 `model_ids` 确认固定模型，空事实必须拒绝，且不得把历史固定模型强塞进选项绕过校验；不兼容时应提示先关闭或调整映射。模型映射的独立 PATCH 与普通 Key 配置 PATCH 必须保留对方并发写入的字段，禁止用事务外读取的旧整行对象覆盖。候选分组模型家族与已映射 Key 的兼容性必须在候选分组和引用 Key 均加锁的同一事务内复核，不能只做服务层预检。无法识别的历史映射策略必须显示为可修复异常，保留原值供核对，并允许直接关闭为“按下游请求选择”，不得静默伪装成已关闭。
- 模型家族在 Key 管理和使用记录中使用同一份规范元数据；界面只显示官方颜色的品牌图标，不在图标旁重复显示“GPT / Codex”等家族文字，但必须通过 `aria-label` 和 Tooltip 保留可访问家族名称。未知家族只能使用带可访问名称的中性图标，不得借用相近品牌；图标容器尺寸固定，不能挤压模型名或导致窄屏溢出。思考程度值使用上游协议的官方英文写法，例如 `low`、`medium`、`high`、`xhigh`，不得翻译为中文档位。
- 图表和排行面板在同一网格内使用固定高度，横向排列时应有一致的顶部与底部边界。
- 使用记录费用必须按账单证据状态展示：`estimated`、`reported`、`reconciled` 即使金额为 0 也显示格式化金额；`unavailable` 只显示“无法估算”和后端白名单原因，不得把为审计保留的旧金额作为账单展示；`none` 才显示破折号。带价格事实的记录展示事实版本、计价模型、操作、协议、币种、单位、来源和用量口径，继续展示请求时冻结倍率供审计，但不得用它重新推导或覆盖价格事实费用或按倍率推导的费用拆分。
- 费用口径对比必须同时展示滚动 24 小时、当前业务日和账户当前业务日，不能把不同时间窗口的差额直接标成漏记；只有同一业务日差额可以作为排查非网关消费、延迟入账或未完成对账的线索。
- 大量待处理变更使用批处理工作台：按状态拆分页签，列表支持搜索、按来源成组选择和全选筛选结果，目标与操作固定在独立操作区；逐行弹窗只作为例外，不作为主流程。
- 网络代理列表只显示名称、协议、脱敏出口、标签、状态、测试结果与绑定数量；认证用户名、密码、订阅 URL、原始节点链接和长错误不能进入表格、Toast 或导入结果。代理选择使用固定尺寸 Popover，选择“直连”或一个已启用代理不得推动渠道编辑表单；禁用的既有绑定必须保留为不可用状态，不能静默改为直连。

## 文案、图标与交互

- 工具按钮优先使用 Lucide 图标，并提供 `aria-label` 与 Tooltip。仅在命令含义不明显时添加短文字。
- 不在 UI 常驻区域解释“这个功能是做什么的”；需要背景说明时放 Tooltip。错误、空状态和风险提示可以直接显示必要文案。
- 刷新、同步、测试等异步操作必须给出可见反馈：禁用态、旋转图标、进度或结果弹窗。测试应展示请求摘要和上游返回，且不得暴露密钥。
- 客户端导入使用分层 Dialog，不在表格行内展开。官方深链、文件配置和设置页参数必须使用不同的动作与位置标签；文件配置显示准确目标文件，设置型配置显示准确填写位置。默认模型只能来自已就绪映射或同步的真实 `model_ids`，缺失时提示并禁止会自行猜测模型的一键导入。具体协议与用量语义见 [客户端导入与配置约束](client-import.md)。

## 响应式与可访问性

- 固定格式的工具栏、指标和图表要定义稳定尺寸与断点网格；小屏改为单列或可横向滚动，不允许文字互相遮挡。
- 所有长值应截断并提供 `title`/Tooltip；金额、Token、倍率、延迟等数值使用一致格式。
- 不使用仅颜色传达唯一含义。状态还需要文字、图标、标签或结构性提示。

## 维护方式

- 新增设计 token、标准组件、页面级布局模式或状态语义时，先在本文件补充规则，再在代码中使用。
- 若现有页面与本规范冲突，以明确的用户产品要求为准，并在同一提交中把规范更新到新的共识。
- 不要通过复制粘贴局部 CSS 形成第二套风格；优先复用语义 token、`PageHeader`、`StatusMetricCard`、表格和 Tooltip 基元。

## 桌面布局与操作密度

- 管理页以列表和操作为主体。使用记录默认收起用量图表，筛选、统计和表头应在桌面首屏可见；筛选与它影响的数据相邻。总览优先展示核心趋势和待处理事项，次要分析放在后面。
- 费用页先明确范围，再展示四个费用状态指标；Token、成功率、耗时使用较轻的摘要层级，不能和费用争夺同等空间。
- 费用页顶部保留费用走势与渠道排行；底部的模型、下游 Key、费用来源、路由结果使用同一组等宽面板。视口达到 1800px 时四列、1024–1799px 时两列、更窄时单列；各明细面板使用相同的 256px 内容区，超出时在面板内部滚动。名称和金额同行对齐，长名称截断并可查看完整提示；请求、Token、耗时、缓存及核对明细按行换行，不能挤压名称或撑宽面板。
- 常用搜索与创建保留在列表工具栏，接入配置、分组及同步等低频操作集中在展开区；不要把全部按钮平铺成多排。
- 系统设置按分类切换，切换不丢弃未保存表单；保存/应用状态和操作保持可见。普通字段解释放在可键盘访问的帮助按钮中，标签仍常驻；凭据留空语义、禁用后果、资金影响和错误提示不可隐藏。
- 弹窗按身份信息、业务字段、高级选项分区；简单身份字段桌面双列，复杂表格保留独立滚动区域。渠道表单的监控和高级设置可按需展开，表单校验失败时应能定位字段；长表单保存操作保持可达。
- 上游变更默认展示完整队列，选中后立即显示固定批量操作栏；单行“分配”与批量“加入分组”共用可搜索的目标 Popover。Popover 明确显示冻结的对象数量、目标名称和筛选外已选数量，点击“加入”即保存人工归组，明确再次指定会替换原人工目标，不再重复弹出确认框；多目标在同一 Popover 勾选后展示完整目标预览并一次提交。忽略和删除复核仍保留各自的确认。“按规则处理”作用于已选项（含筛选外已选项）或没有选择时的当前筛选结果，每批最多 100 项。先正式预览各项去向，再逐项重新核验并通过带 evaluation_token 的执行入口处理；不能将规则建议经人工覆盖入口写成永久 override。
- 建议变化、代次变化、证据缺失和规则冲突保持待处理。请求失败停止剩余执行，展示已完成/未完成结果，不能盲目重试不确定结果。受管 Key 删除仍保留独立身份核验与复核依据。

- 密钥管理页直接以筛选和列表为主体，不再在列表前放四张大统计卡。“全部 / 启用 / 停用 / 路由异常”使用带计数的紧凑筛选按钮，配合 Key 分组和搜索。刷新、管理与接入、创建放在页面标题右侧；管理区按需展开，保存分组、候选管理及接入工具入口。
- 密钥主表保持七列：密钥、路由、候选管理、模型映射、费用、状态、操作。普通行约 70px，两行信息有主次；名称左对齐且不与分组平分宽度，品牌图标在名称前，小分组标签在名称后，第二行显示密钥及复制/显隐。候选管理独立成列，候选范围文字即管理入口；模型映射约占表宽 12%，只保留策略和简短模型摘要，完整内容通过提示与编辑弹层查看；智能路由下可直接打开固定候选选择器，只有保存后才切换实际路由。
- 客户端配置和连通性测试在行尾直接可达，编辑和删除放在更多菜单，名称也可打开编辑。名称、Key 分组和候选范围使用独立编辑弹窗，不能挤占表格列宽。费用仅常驻今日/累计两行，请求数和 Token 在提示中查看；启用状态和实时并发不与路由可用性合并。
- 候选管理默认一行展示全局名次、渠道/分组、状态、价格、延迟、得分和操作。倍率拆分、样本量和评分细节通过提示查看，不能重复堆叠外层身份、状态与内层卡片；实际阻断原因仍可见。缺快照成员只展示身份及不可见状态，不虚构价格与操作。
- 路由预览模型在同一 Popover 搜索选择；手选后固定在当前 Key 的浏览器会话，后台映射报错或刷新不能覆盖。库存暂缺时保留手选名称并暂停该模型预览，模型恢复后继续使用；不把缺失模型注入可选列表。切换 Key 或实际候选范围后按有效模型重新恢复，单次库存缺失不得删除保存偏好。

- 密钥主表的模型映射使用就近 Popover 独立编辑与保存，不能展开撑高整行；本列常驻策略与实际模型两行，不重复边框和“模型映射”标签，关闭映射仍提供本列保存/取消。创建与最近使用时间放在身份提示中，主表优先给路由、候选、密钥和操作分配宽度。
- 所有“配置/导入”入口进入统一客户端配置弹窗，客户端列表直接提供 CCSwitch 入口，沿用已有协议兼容门禁。配置预览使用主题浅色信息面和正文色，深色主题随 token 切换，不硬编码深黑代码块。
- 点击测试只打开准备界面；管理员可选已同步模型或输入请求模型，并选择 Chat Completions、Responses 或 Messages 协议；点击“开始测试”才发送一次请求。保留现有 Key 测试凭证、路由与模型映射语义，显示真实请求可能计费；运行中禁止重复发起或关闭后混入其他 Key 的结果，提供“停止等待”及 60 秒等待上限，不自动重发；停止等待后明确结果可能未确认，不宣称服务端已取消。结果区只显示状态、耗时和响应，请求详情按需展开，不重复 Key 名称、模型与协议。

- 客户端列表使用各项目的品牌图标，复用已有品牌图标包或随构建附带的官方资源；保持 20px 命中区内等比显示，不重绘为通用线条图标，不在运行时请求外部图标 URL。单色图标适配深色主题，彩色图标保留原色。
- 连通性测试的模型与协议控件等高、底部对齐。模型选择使用独立搜索 Popover，每次展开清空搜索并显示全部已同步选项；当前选中值不能充当过滤词，输入新模型 ID 后显式选择。手选模型按 Key 在当前浏览器保存，重开或刷新后恢复，手输 ID 同样保留；已同步列表明确不再包含原列表选项时使用当前默认模型，暂时没有模型列表不清除记忆。恢复选择不发请求，仍须点击“开始测试”才发送请求。

- 候选管理列第一行显示渠道：固定模式显示已配置目标，智能模式标记“最近”并展示最近一次成功真实请求的渠道；第二行显示候选分组和数量，整格入口打开候选管理。没有真实记录时显示“尚无使用记录”，不得把预览第一名冒充实际使用渠道。完整分组、模型和请求时间放在提示中。测试、模型检测、探测及管理请求不能改变这项记录。后台复用已有最近请求模型查询返回渠道事实，不增加逐 Key 的历史查询，也不改变路由或会话亲和。

- 使用记录以紧凑的两行记录为主，普通行约 54px，不通过缩小正文隐藏信息：Key 与时间合并，倍率独立列，费用只常驻金额与状态；下游 IP 默认直接展示，并保留列显隐偏好与本地定位入口。倍率列只显示一个请求时冻结的分组倍率，不重复排列“入 / 出”；明确零值显示为 0x，未知显示为 —，输入/输出差异、原始倍率及资金系数在提示和详情核对，不能因为已有价格事实而隐藏。渠道 / 路由列的渠道名保持 13px，分组和路由辅助标签固定为 11px、常规字重及弱化文字色，至少比主信息小 2px，桌面全局样式不得重新放大。请求明细标题与条数同行，模型列分配约 21%–22% 宽度，以上下两行直接显示实际派发模型与上游响应声明，用第二行向下转右的弯箭头指向返回模型，不常驻“请求 / 返回”文字；有记录的思考等级以英文紧凑标签紧邻请求模型，模型名过长时只截断名称并保留等级。辅助技术与 Tooltip 仍区分请求和返回，不再显示一致、版本差异或模型差异标签。去除首尾空格后模型 ID 不同（包括版本后缀或大小写差异）时仅将返回模型名标红；未报告保持中性。长模型名截断，整格可点击打开详情，详情完整展示两者并沿用相同颜色；映射前模型仅在存在映射记录时单独展示，计费模型仍独立，不能混淆。模型名称本身不构成真实性证明。

- 渠道主表使用八列：渠道与协议、状态、余额与今日消费、充值成本、订阅、分组与倍率、调用与更新、操作。桌面表宽预算固定，渠道名可直接编辑；右侧同步、编辑、测试、监控启停、充值/订阅、兑换码、管理密钥、清空凭据和删除分别作为按钮常驻展示，不再折入更多菜单。操作区固定网格，视口至少 1800px 时五列、其余桌面三列，保持 36px 命中区；每个图标有独立名称与悬浮说明，异步操作显示忙碌并禁用重复触发。直连渠道不显示不适用的充值、兑换和远端密钥管理；清空与删除保留原确认流程及待删除状态门禁。“分组 / 倍率”直接按有效倍率排序展示分组标签，固定预览区内自动换行（普通桌面两行，大桌面三行）；能放下的全部显示，不用最低倍率加总数替代。仅实际超高或名称被截断时提供整格点击的 Popover，完整内容在浮层内滚动，不撑高表格；缩放或刷新后重新核对溢出，全部能放下时取消展开入口。订阅只展示状态与最低剩余比例，详情按需打开。订阅读取失败必须显示异常，不能把未知用量显示为不限。
- 参数配置按任务分区切换，已挂载表单保持草稿；通知渠道与告警规则并排常驻；模型价格列表分页，切换列表或搜索回到第一页。列表内统计使用紧凑文字摘要，独立指标卡仅用于页面级核心指标，避免在通知、验证码和事件面板内重复嵌套大卡片。
- 标准编辑弹窗使用 `DialogContent formLayout` 与 `DialogBody`：标题、底部操作固定，中间表单单独滚动。保存类请求通过 `Dialog busy` 禁止 Esc、遮罩、关闭按钮和对象切换，失败仍保留草稿；可取消的测试与读取操作沿用各自取消语义。校验失败时展开对应区域并聚焦字段，不让错误字段藏在高级选项中。
- 保存成功但后续列表刷新失败时必须区分两者；依赖版本号的配置在重新加载成功前不能继续提交，提供原位重新加载入口。侧栏底部使用带提示的紧凑工具按钮，优先为页面入口保留空间。

## 1080P 及以上桌面布局（当前优先规范）

- 以 1920×1080 为主验收尺寸，同时检查 2560×1440 和较窄桌面。优先利用宽度建立主次分区，不能把紧凑理解成小字体、小按钮或大量隐藏；本节取代早期“尽量收起内容”和独立小指标卡的约定。
- 页面标题 24–28px，主指标 30–34px，正文/常用操作 14px，辅助数据一般 13px；表格内最小辅助文字通常为 12px。渠道管理按当前字号偏好单独使用 16px 渠道名称、11px 分组与倍率标签，桌面样式不得将标签重新放大。常用控件高 40px，次级按钮 36px，状态标签不承担正文。主区域之间留 20–24px，相关内容在完整面板内用轻分隔组织。
- 指标采用共享白色摘要面板，不重复套小卡片。页面主体是完整表格、图表或工作区；不要为了填满屏幕增加无意义装饰，也不要将数据压成稀疏的小块。
- 渠道页直接显示全部适用的操作按钮，并展示多个分组倍率；弹层承接全部分组和长错误。密钥、使用记录的主要渠道、模型、倍率及费用继续常驻显示。
- 网关配置按路由策略、模型价格、渠道维护、健康状态四个任务分区；评分、故障、缓存与会话参数在同一策略工作区分行呈现，左侧分区标题、右侧并排字段。通知渠道与所有告警规则并排，规则不再逐小项切换隐藏。模型对比筛选允许换行展示，不能只给一条难以发现的横向滚动条。
- 常用编辑弹窗桌面宽度 768–1024px，大型候选/详情工作台可进一步加宽；保留固定操作区，相关字段并排，必要说明直接展示。仍须在较矮视口下滚动正文并保持错误与保存按钮可见。

## 鹈鹕检测工作台

- 鹈鹕画廊以桌面每行五张的动画画廊为主体，全站合计最近 12 次，依次排成 5 / 5 / 2 三行，不虚构示例为检测结果。卡片只展示渠道/分组、模型、两项本地校验与时间，完整题目和响应在放大详情中查看。
- 鹈鹕画廊的糖果题与 SVG 校验只表示本轮作品的校验结果，不构成模型掺水或渠道健康结论。渠道管理和渠道监控不得据此显示“掺水异常”“检测不可用”等标记，也不得将画廊结果纳入健康状态、需要关注数量、筛选或排序；相关结果在画廊内查看。
- 卡片缩略图占满卡片宽度，按 SVG 原始比例自适应高度，完整显示画面，不裁切或拉伸。画廊通过等高网格统一所有卡片和预览区的高度，以足够容纳最高作品为准；较矮作品与失败占位在预览区居中，底部信息区对齐。全部无动画时使用占位最小高度；窗口缩放时由 CSS 自动重新排版。放大详情保持完整适配，原始 SVG 与复制内容不变。
- SVG 只以图片上下文显示，禁止 innerHTML、同源 iframe 或执行模型返回的脚本。提供全局及详情暂停按钮；大结果不跟随全局轮询反复下载，手动运行结束或刷新时更新。
- 自动状态称为“糖果题通过”或“SVG 校验通过”，不能将结构校验冒充画面质量审核；明确画面由管理员核对。运行设置说明每轮两次请求和固定 12 份结果，不再提供容易混淆的动画保留天数。

- “鹈鹕画廊”页面首屏提供渠道、分组、模型三级手动选择，模型仅来自所选分组实时返回的列表，不自动挑选默认模型；选择变化即时按浏览器保存，刷新和重开不得覆盖。旧选择失效时保留名称并禁止开始检测，不静默改目标。重新选渠道/分组时明确清空下级选择。模型读取失败允许原位刷新，不显示其他分组的旧列表。检测期间锁定选择并阻止重复提交，记录与详情展示实际渠道、分组、模型和协议。
- 运行日志位于选择区下方，开始后展开，允许折叠且不停止检测。标题保留渠道/分组/模型与等待秒数；有界滚动区按步骤显示请求参数和纯文本响应，不在作品卡片或表格中展开长文本。使用记录分别标记“糖果题”和“鹈鹕绘制”，未确认费用沿用未知状态，不展示为免费。

## 充值成本工作台

- 充值成本弹窗采用固定宽高与固定标题区，各页签共享同一窗口尺寸，内容仅在内部滚动；以原始余额、折合资金余额和系数三项摘要为入口，分为充值处理、成本校准、充值历史、分组倍率四个页签。真实充值与校准不得共用保存入口或伪装成同一操作；校准保留一次明确确认、原因及版本/账户/计价单位围栏，并直接说明是否归档待确认记录。
- 待确认记录按实际发生时间从早到晚展示，仅最早一条可以入账；存在待确认时不再展示可提交的手工新增表单。历史补录由后端使用当时快照计算，不能用当前余额生成看似精确的预览或错误阻止已消费后的补录。
- 读取期间、版本冲突或刷新失败后暂停所有写操作，允许原位重新加载；已保存但读取失败必须明确说明保存结果。来源渠道变化和迟到读取不能覆盖当前结果。校准确认和网络提交共享忙碌门禁，不重复提交。普通充值结果不确定时引导核对历史，不能直接重复发送原表单。
