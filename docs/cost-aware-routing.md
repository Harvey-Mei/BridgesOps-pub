# 成本路由与使用记录

## 已接入

- 使用记录分开保存客户端请求模型、实际派发模型、响应声明模型和最终账单模型。仅比较派发与响应声明；日期后缀标为版本差异，缺失记录保持未知。这不是模型真实性证明。
- 请求时冻结的输入、输出倍率始终可以查看，包括明确的零倍率；原始倍率与资金系数在详情核对。确认账单（含零费用）优先于本地倍率估算。
- 对账不能将缺失或 `null` 的 `actual_cost` 当作免费请求。不同 TTL 缓存写入不能压成同一个较低单价；当前用量无法拆分时该分项保持未知。
- 明确指定模型的智能请求，在完整候选比较集都有匹配价卡时，用每百万混合 Token 的参考成本评分：共享同模型最近七天真实成功请求的输入/输出比例，至少十条；不足时暂按各半。输入成本结合现有有界缓存读取统计，未命中部分取输入与缓存写入较高价保守计算，再乘分组倍率和资金系数各一次。它是可比较的预测指标，不是本次请求账单。
- 价卡读取只在后台进行，每次查询最多 2000 路由、750ms；最多两个加载任务和八份内存快照。冷启动、过期、缺价、身份变化或无法比较时，整个比较集暂用原倍率评分。

## 阶梯规则的边界

当前渠道价格同步支持两个连续区间的 `whole_request`（整单计价）与任意有效正阈值。手工全局价格仍限定现有 272000 阈值。多档、`marginal`（超额累进）、分时价格、峰时倍率和表达式计价尚未完整表示，不能声称已读取并用于精确计算；按次收费也不混入 Token 单价。阶梯价目前不用于路由预测：发出请求前缺少可靠输入 Token 数，不能默认最低档。最终费用仍依赖严格身份与用量匹配后的账单。

模型映射保留现有“先选候选顺序，再过滤映射模型”的规则；固定路由不采用智能评分。会话亲和继续按 Key、会话哈希与模型隔离，并检查成本。

## 慢响应检查

智能文本接口等待有效输出超过 30 秒后，向同一冻结目标、模型和协议发送简短检查。检查在途时不叠加，完成后间隔 30 秒再检查；单次从实际派发开始最多等待两分钟。因此第一次完全无响应的检查通常在主请求约 150 秒时结束等待，而不是主请求两分钟硬截止。

主请求未受理时可以换候选；可信生命周期事件会立即保存受理事实，已有可信受理证据时必须结束并报错，不重发。后续容量提示、解析失败或断流不能撤销受理；隐藏的容量提示也不能混入客户端的合成终止正文。开始正文、思考或工具参数输出后停止检查。固定路由、图片生成及原有不可重放保护保持独立。账户容量、同目标合并、四路并发及费用记录写入预算共同约束检查；本地饱和不代表渠道故障。

检查只发送固定短文本，不携带用户内容或工具；记录为内部探测，保存可用的费用证据并进入适用的费用对账流程，不展示在用户使用记录，也不把短请求耗时混进正常延迟评分。

## 参考与取舍

接口行为参考 [Sub2API v0.2.5 模型广场](https://github.com/Wei-Shaw/sub2api/blob/v0.2.5/backend/internal/service/model_plaza_service.go) 和 [使用记录模型核对](https://github.com/Wei-Shaw/sub2api/blob/v0.2.5/frontend/src/components/admin/usage/UsageTable.vue)。实现使用本项目已有网关、存储和审计链，未复制其实现源码。

结合 [Sub2API v0.2.5](https://github.com/Wei-Shaw/sub2api/releases/tag/v0.2.5) 和 [NewAPI v1.0.0-rc.37](https://github.com/QuantumNous/new-api/releases/tag/v1.0.0-rc.37) 的功能，本轮优先补齐与费用、路由和日常操作直接相关的部分：

| 能力 | 当前处理 |
| --- | --- |
| 请求与响应模型核对 | 保存响应声明，区分版本差异、名称不一致及未提供；不以声明替代模型质量检测。 |
| 费用和缓存成本 | 分开保留估算、直报与最终对账；可比较的候选结合实际缓存表现和模型单价评分。 |
| 模型目录与计价规则 | 使用精确渠道、分组、模型的受信目录；支持上述两档整单价，复杂规则保持未支持。 |
| 批量操作与表单一致性 | 上游变更集中选择、分配；候选及配置保留草稿和选择，保存失败可原位修复。 |
| 运行边界 | 保留本项目的受理后不重放、固定路由和生图防重复计费规则。 |

表达式执行器、平台插件和与网关成本无直接关系的管理功能没有纳入本轮；缺少可比较价格时整组回到倍率评分，不把未知价格当作零价。
