# 鹈鹕画廊

当前题组是 `pelican-v1`：每轮分别请求一幅鹈鹕骑自行车 SVG 动画和一道随机糖果题。
动画使用随机场景与独立校验码；糖果题的数量随机生成，程序计算最少取糖数并核对严格 JSON 与校验码。
页面自动结果仅代表题目与 SVG 结构校验，鹈鹕形体、构图和骑行动作由管理员并排观察；不调用视觉评分模型。
检测不证明模型身份，也不因单次结果禁用路由。

## 数据边界

- 题目在 BridgeOps 进程内随机生成，使用当前渠道分组已有的受管 Key 直接请求。
- 不调用第三方检测服务，也不向第三方发送 Key、题目、响应或评分。
- 鹈鹕输出上限为 8192 Token，糖果题上限为 2048 Token。SVG 最多 96 KiB、2000 个元素、48 层、64 个 SMIL 动画；不运行浏览器或截图进程。服务器解析 XML 并校验完整 CSS，拒绝脚本、事件处理器、外部资源、use/symbol、mask、滤镜及过快动画。管理界面只通过图片上下文预览，可暂停和放大，绝不将生成代码插入管理页面 DOM。
- 单项题目、期望值和成功响应摘要均有长度上限。安全 SVG 单独完整保存，不受旧的 2048 字符摘要截断。新产生的错误只保存固定类别和可选 HTTP 状态码；上游或代理错误体、认证头（包括 Basic 与 Proxy-Authorization）、短 token、URL query 与 password 不得入库或经管理员 API 返回。历史记录中的旧错误在管理员 API 中也只返回该安全格式；清理其数据库存量需单独的数据迁移。
- 检测证据保存在 `model_check_targets` 与 `model_check_runs`。实际发起的糖果题和鹈鹕绘制请求分别写入使用记录，以 `route_reason=model_check` 区分，保存渠道、分组、模型、协议、耗时、Token 与缓存用量；失败请求同样留记录，准备阶段尚未发起请求的失败不计入使用记录。这些内部请求不参与路由延迟、缓存收益评分、会话亲和或健康恢复，也不能反向生成检测目标。
- 费用没有可信依据时显示未知，不把零值当成免费。支持管理端用量查询且存在匹配依据的请求继续异步严格对账；冻结请求时的资金系数、账户身份和计价单位，真实身份/单位变化或不可信资金状态拒绝覆盖费用，临时查询错误按有界退避重试。没有管理端账单查询的渠道保留费用未知。

## 目标发现

检测粒度为“渠道 + 分组 + 实际模型 + 协议”。目标只来自：

1. 已加入任一候选分组的渠道分组；或
2. 最近 30 天承载过真实成功下游请求的渠道分组与模型。

`latency_probe`、`api_test` 和 `model_check` 等内部流量不能生成新目标。渠道监控关闭、渠道有
同步错误或组级模型检测关闭时不会继续模型检测；低余额只暂停最终路由，不暂停模型检测。
延迟方面不对健康分组做周期探测，仅对仍处于当前精确 generation 冷却阶段的分组执行恢复探测。
模型检测或恢复探测返回账户余额不足时只更新当前渠道的余额事实，不写组级冷却。余额有效阈值为用户配置值与
`0.1` 中的较大值，余额恢复后目标可自动重新进入路由。

## 状态与告警

- `pending`：尚未完成检测，或第一次网络/协议/HTTP 错误尚不足以判定不可用。没有任何成功模型响应的检测轮只记录 `error`；默认零值不会参与历史基线比较，也不会覆盖目标上一次得分。
- `healthy`：本轮糖果题和 SVG 本地校验通过，不代表视觉质量通过。
- `suspect`：本轮已出现能力异常；第一次异常会立即在管理员页面显示。
- `unavailable`：连续两轮无法完成检测。

连续异常达到 `alertFailures` 后才发送通知，模型族硬不匹配会立即激活告警。已激活告警需要
连续两轮健康才恢复。第一阶段只告警和留证，不自动禁用渠道、分组或 Key，也不修改路由。

## 调度与预算

`scheduler.modelCheck` 控制检测：

- `runsPerDay`：每天平均执行轮数；
- `concurrency`：定时和管理员手动检测共享的全局并发上限；
- `maxTargetsPerRun`：单轮最多目标数；
- `probesPerTarget`：兼容保留配置键，当前题组固定为 2，不因旧值较小而提高既有请求预算；
- `requestBudget24h`：定时和手动检测共享的滚动 24 小时请求上限；
- `timeoutSeconds`：糖果题超时，默认 60 秒，可设 10–180 秒；
- `pelicanTimeoutSeconds`：鹈鹕绘制超时，默认 600 秒，可设 60–1800 秒；
- `alertFailures`：连续异常告警阈值；
- `historyDays`：轻量预算/状态审计的保留天数，不控制动画画廊。

默认配置关闭。启用后默认每天 3 轮、并发 2、每目标 2 个请求、24 小时最多 72 个请求。

## 管理员审计

管理员后台展示四列三行画廊，整个页面合计仅显示最新 12 份完整结果，不按目标分别累计。每次结果入库后，在事务内串行压缩窗口外的题目、回答与 SVG；首次升级的旧证据按每批最多 500 行逐步清理。只保留轻量请求计数、时间和状态台账直到审计期限，以保证 24 小时预算和跨轮告警恢复不被清理重置。不同账户身份的旧结果不会在当前渠道下展示。

页面同时支持按状态、渠道和模型筛选检测目标、启停目标、立即检测以及查看最近证据。单项失败证据只显示固定错误类别和可选 HTTP 状态码；渠道管理和渠道监控只显示固定状态标签，长证据必须在带上下文、
可复制的详情弹窗中查看，不能展开表格行。

网关响应正文出现 `<thinking>` 时，普通请求仍按原协议返回，但管理员使用记录会在对应请求
详情中保存固定告警和实际路由信息，不保存完整对话。`402 Payment Required` 只触发当前尚未
输出内容的请求可以尝试下一候选并留下回退审计；共享停用状态只服从渠道监控保存的余额和健康数据。

## 参考

产品形式参考[鹈鹕观察站](https://manxue.facingagi.com/)：SVG 骑行动画和糖果题分开检查。本实现独立编写随机题组与本地校验器，不连接参考站，也不使用其访客检测服务。旧题组分数不参与新题组基线比较。

## 手动选择

页面先选渠道和分组，再从该分组受管 Key 实时读取 `/v1/models`，手动选择模型，点击“开始检测”后才发送推理请求。读取失败明确提示并允许刷新，不用缓存或全局列表兜底。三项选择立即保存在当前浏览器，重开或刷新后原样恢复；选项消失或渠道账户 revision 变化时保留文字并要求重新选择，不回退到其它模型。

`GET /model-checks/manual-options` 返回已有候选或近期真实流量中的渠道分组，最多 10000 项；`GET /model-checks/manual-models` 按渠道、分组、协议和账户 revision 读取该组的实时模型，最多 2000 项，复用渠道代理、Key 与分组派发校验。`POST /model-checks/run` 再次读取实时列表并核验完整选择，渠道名以服务端为准。手选新模型只创建非自动发现的审计目标，不扩大定时任务集合，也不能用内部检测流量生成新来源。检测预算、并发、停用偏好及最近 12 份完整结果规则继续适用。结果冻结渠道、分组、模型、协议；长期请求完成只更新检测状态，不能覆盖运行期间的管理员启停或后台发现状态。

手动运行使用 SSE 逐步显示请求路径、请求参数、响应状态和有界响应正文，每 15 秒保活。日志不含认证头或 Key，浏览器只保留当前轮最多 40 条日志；正文以纯文本显示，不执行返回代码。日志可展开或折叠，折叠不取消请求；离开页面断开请求，不自动重发。界面显示等待时间，鹈鹕独立使用较长超时。相同目标排队时取消会释放本地并发与预算，不继续占用长任务队列。

检测请求 ID 不得包含实际受管凭据；派发围栏拒绝时不发送“已发起”事件且不生成使用记录。使用记录 API 通过白名单 `model_check_kind` 区分糖果题与鹈鹕绘制，不输出原始 `route_details`。
